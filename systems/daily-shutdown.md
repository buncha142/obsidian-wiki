# Daily Shutdown — SOP ปิดวันงาน 30 นาที

## หลักการ

งานที่แทรกเข้ามาระหว่างวัน (โทรศัพท์ ไลน์ คนมาขอความช่วยเหลือ ไอเดียที่ผุดขึ้นระหว่างประชุม) ถ้าไม่มีที่ให้ "จอด" ทันที จะกลายเป็นภาระต้องจำในหัว — นี่คือต้นตอของอาการ "งานล้น/ลืมงาน" และ "ถูกขัดจังหวะตลอด"

หลักการเดียวกับ [[systems/phone-jail]]: แก้ด้วย environment design ไม่ใช่ willpower — สร้างจุดจอดเดียว (Single Inbox) และจุดเคลียร์คงที่ทุกวัน แทนการพึ่งความจำ

## Single Inbox — จุดจอดเดียว

ระหว่างวัน เมื่อมีเรื่องใหม่เข้ามาที่ไม่ใช่ Big 3 ของวันนี้:

1. เขียนลงช่อง `00_Inbox/` (ไฟล์เดียว หรือกระดาษโน้ตข้างมือถ้าไม่สะดวกเปิดคอม) **ทันที ไม่ต้องตัดสินใจ**
2. กลับไปทำงานเดิมต่อ — ห้ามหยุดเพื่อ "จัดระเบียบ" เรื่องที่เพิ่งจด
3. เคลียร์ inbox เฉพาะตอน Daily Shutdown เท่านั้น

## ขั้นตอน Daily Shutdown (18:30–19:00)

| นาที | ทำอะไร |
|---|---|
| 1–10 | เปิด `00_Inbox/` — ไล่ทีละรายการ: งานไหนมี deadline/สำคัญ → ย้ายเข้า `TASKS.md` หมวดที่ตรง (Computer/Phone/Personal/Office); งานไหนเป็นข้อมูลอ้างอิงระยะยาว → ส่งเข้า wiki ทีหลังด้วย `/wiki-update`; งานไหนไม่จำเป็น → ลบทิ้ง |
| 11–15 | เช็ค `TASKS.md` — ขีดถูกงานที่เสร็จวันนี้ ย้ายไป Done |
| 16–20 | เขียน `DAILY_LOG.md` — บันทึกสิ่งที่ทำเสร็จวันนี้ 1 บรรทัดขึ้นไปตามรูปแบบเดิม |
| 21–25 | เปิด Mi Fitness บันทึก Sleep Score / Deep Sleep / REM / HR / SpO2 ลง [[health/fitness/logs/daily-template]] |
| 26–30 | ตั้ง **Big 3 เบื้องต้นของพรุ่งนี้** — ดูจาก `TASKS.md` หัวข้อ `## 🎯 สัปดาห์นี้` (มาจาก [[systems/weekly-review]]) เลือก 3 งานที่สำคัญที่สุด เขียนลง `## 🎯 วันนี้ (Big 3)` ไว้ล่วงหน้า พรุ่งนี้เช้า 08:45 แค่ทบทวน ไม่ต้องคิดใหม่ |

## เงื่อนไขจบ

Shutdown เสร็จเมื่อ `00_Inbox/` ว่างและ Big 3 ของพรุ่งนี้ถูกเขียนไว้แล้ว — ถ้าทำไม่ทันใน 30 นาที ให้หยุดตามเวลา (ต้องไปทำวัตรเย็น 19:00) แล้วทำต่อในรอบถัดไป ไม่ยืดเวลาเข้าไปชนช่วงทำวัตร
