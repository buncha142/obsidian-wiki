# Buddhist-Era (พ.ศ.) Date Picker Pattern for html-data-editor Tools

## Problem

Tools generated by the `html-data-editor` skill (e.g. `coordination-log.html`) store dates as free-text Thai Buddhist-era (พ.ศ.) strings, like `"2569-07-06"`. The native HTML `<input type="date">` element only understands Gregorian years and renders/parses incorrectly if fed a พ.ศ. string directly — so it can't simply replace the existing text field without changing the stored format.

## Solution

Keep the visible field as plain text (unchanged storage format) and layer a hidden native picker behind it:

- `<input type="text" id="ef-date">` — the original field, untouched. This is still what gets saved/exported.
- A small "📅" button next to it.
- `<input type="date" id="ef-date-picker">`, hidden from view.

Flow:
1. **Button click** — read the current พ.ศ. text, convert to Gregorian ISO (`YYYY-MM-DD`, year − 543), write it into the hidden date input, then call `showPicker()` on it (falling back to `.click()` for browsers without `showPicker()` support).
2. **On `change`** of the hidden date input — take the picked Gregorian date, convert back to พ.ศ. (year + 543), and write the result into the visible text field.

The conversion is pure regex-based splitting of `YYYY-MM-DD` plus an integer offset on the year — no date library needed.

## Why this works

It never touches the storage/export format. The hidden picker is purely a UI convenience layered on top of the existing text-based schema, so any downstream code reading `coordination-log.html`'s data keeps working unchanged.

## Reusability

This is a reusable pattern for **any** `html-data-editor`-generated tool that stores พ.ศ. dates as text and wants a calendar-picker UX without migrating the storage format. ^[inferred]
